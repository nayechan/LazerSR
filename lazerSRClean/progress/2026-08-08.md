## 구간 선택 + 상세 모드

플롯 안에서 드래그하면 흰 세로선 두 개로 구간이 잡히고, 좌상단에 그 구간만의 정확도 3종, 우상단에 그 구간만으로 잰 sunnySR pill이 뜬다.

- `Calculators\ManiaSectionAnalysis.cs` 생성 — 정확도 3종 / 구간 판정 추출 / 구간 임시 `ManiaBeatmap` 조립
- `SunnyManiaDifficultyCalculator.Calculate`에 `weightedNoteCountOverride` 선택 인자 추가 + `CalculateWeightedNoteCount` 신설
- `Strain` 생성자에 같은 인자 추가 — 짧은 맵 보정 `W/(W+60)`의 W만 교체
- `ResultsJudgementScatterPatch` Postfix에 `playableBeatmap` 인자 추가, 생성자를 `(ScoreInfo, IBeatmap)`으로 정리

**구현하며 정한 것**:
- **정확도 3종은 320 판정의 가중치와 분모만 다르다** — 레거시 300 / lazer 305 / pp 320. 나머지(300·200·100·50·0)와 집계 방식은 동일
- **정확도용 판정 목록을 점 목록과 별개로 보관한다** — 산점도는 미스를 버리지만(`TimeOffset`이 클램프된 상수) 정확도는 미스가 분모에 들어가야 한다
- **구간 sunnySR은 raw만 구간에서 뽑고 W는 전체 맵 값을 대입한다** (사용자 지시). 계산기에 선택 인자를 추가하는 방식을 택했다 — 역산 방식은 `>9.0` 리스케일까지 풀어야 해서 상수가 두 곳에 복제된다
- 전체 맵 W는 strain 평가 없이 정렬 + LN 가중 합만으로 구한다. BDL에서 1회만 계산
- **경계 판정 기준이 정확도와 sunny에서 다르다** — 정확도는 점이 찍히는 위치와 같은 `GetEndTime`, sunny 맵은 노트를 쪼갤 수 없으므로 `StartTime`. 구간이 손끝으로 정해지는 값이라 무해
- 입력 레이어는 `Alpha=1`이어야 한다 (0이면 `IsPresent`가 false라 입력이 안 온다). 맨 위에 배치
- **드래그 없는 클릭은 `OnClick`으로 받는다** — 드래그가 있었으면 발화하지 않으므로 `MouseUp` 순서에 의존하지 않는다. 4px 미만 드래그도 클릭으로 간주
- 정확도 박스는 흰 라운드 + 검정 글씨, 각 행은 **양축 고정 `Container`** (AutoSize 즉사 패턴 회피)

## 구간 연습

구간 연습 버튼을 눌러 그 구간만 플레이한다. 종료·사망·나가기 전부 결과창으로 복귀하며 아무것도 저장·제출되지 않는다.

- `Screens\SectionPracticePlayer.cs` 생성 — `Player` 직접 상속 + 같은 파일에 `SectionPracticePlayerLoader`
- `Screens\SectionPracticeBeatmap.cs` 생성 — 원본에서 구간 밖 노트만 걷어낸 `WorkingBeatmap` 사본
- `Screens\ILocalOnlyPlayerLoader.cs` 생성 — 리더보드 스킵용 마커
- `Patches\InfiniteTrainingLeaderboardSkipPatch.cs` → **`LocalOnlyLeaderboardSkipPatch.cs`로 개명**, 타입 하드코딩을 마커 인터페이스로 교체. `InfiniteTrainingPlayerLoader`도 이 인터페이스 구현

**서버 격리** (무한 트레이닝과 동일 + 한 가지 더):
- `Player` 직접 상속(제출·관전 경로 없음) / `ShowResults=false` + `ImportScore` no-op / `CreateResults` throw / `PrepareReplay` no-op / 리더보드 조회 스킵
- **`InitialActivity => null`이면 서버로 아무것도 전송되지 않는다** — 결과창과 `PlayerLoader`의 활동 상태가 원래 null이라 브로드캐스트 값이 **바뀌지 않고**, `OnlineMetadataClient`는 변화가 있을 때만 `UpdateActivity`를 보낸다

**1차 구현이 실패했고 그 원인이 중요**: 처음에는 맵을 자르지 않고 원본 전체를 플레이하며 `EditorPlayer` 방식(구간 이전 노트를 리플레이 판정으로 채우기 + 강제 미스 방지)을 썼는데, **시작하자마자 종료**됐다. `CreateGameplayClockContainer` 안에서 `Reset()`을 부르면 컨테이너가 아직 트리에 붙기 전이라 seek이 반영되지 않고, 첫 프레임의 `CurrentTime`이 **결과창에서 재생 중이던 곡 위치**로 읽혀 종료 조건이 그 자리에서 성립했다.

**맵을 실제로 자르는 방식으로 전환하니 코드가 순감했다** — 구간 이전 노트 채우기, 강제 미스 방지(internal 멤버 리플렉션 3개), 체력 예외 처리, 시각 기반 종료 감시가 전부 사라지고 약 120줄이 줄었다. osu!가 보기엔 그냥 짧은 맵이라 완료 판정·점수·정확도가 평소 경로로 맞는다.

**`WorkingBeatmap` 래퍼가 가능함을 뒤늦게 확인**: 초기 조사에서 "오디오 위임 불가"로 판단해 포기했으나 틀렸다. `Beatmap`/`GetBackground`/`GetStream`이 public이고, **`TryTransferTrack`(public virtual, 구현이 `target.track = Track` 한 줄)** 이 `BeatmapInfo`를 공유하면 로드된 트랙 인스턴스를 그대로 넘겨준다. 추상 멤버 중 리플렉션이 필요한 건 `GetBeatmapTrack` 하나뿐.

**그 외 구현하며 정한 것**:
- 시작은 `StartGameplay()` override에서 `Reset(구간시작 − 1500 × 배속, startClock: true)`. **체감 기준**이라 배속을 곱한다
- 종료는 `ScoreProcessor.HasCompleted` → 1초 뒤 `Exit()`
- 구간 끝은 **마지막 노트의 `GetEndTime()`** — 경계에 걸친 롱노트를 끝까지 잡는다
- `Clone()`은 `MemberwiseClone`이라 `HitObjects` 리스트가 공유된다. **반드시 새 리스트로 갈아끼워야** 원본이 오염되지 않는다
- 다른 어셈블리에서 `protected internal` 멤버(`GetSkin`)를 재정의할 때는 `protected`로 선언해야 한다

**중요한 발견 — lease가 원복해주지 않는다**: `OsuScreenStack`이 새 화면의 의존성을 **직전 화면의 의존성을 부모로** 만든다(`CreateLeasedDependencies`). 결과창이 이미 Beatmap/Ruleset/Mods를 lease 중이라 우리 로더는 새 lease를 뜨지 않고 사본만 받는다 → 이중 lease 예외는 안 나지만 `ReplayPlayerLoader`가 기대는 "lease가 알아서 원복"이 성립하지 않는다. 셋 다 `OnExiting`에서 직접 되돌린다.

## 컬럼 필터

`[단노트/롱헤드/롱테일]` 여백 `[1..n]` 여백 `[구간 연습]` 레이아웃.

- 컬럼 버튼 개수는 `ManiaBeatmap.TotalColumns`가 정한다. 초록, 전부 기본 활성
- `allPoints`가 `(NoteKind, Column, Point)`가 되고 두 묶음이 **교집합**으로 걸린다
- **정확도는 컬럼 필터를 따라간다**(활성 컬럼의 판정만 집계). 노트 종류 필터는 정확도에 관여하지 않는다(기존 동작 유지)
- **sunnySR pill과 구간 연습은 필터와 무관** — mania 난이도는 컬럼 간 상호작용이 본질이라 일부 컬럼만 남긴 값은 원본과 무관하다
- 묶음 사이 여백은 첫 버튼의 `Margin.Left`로 준다 (중첩 컨테이너를 만들지 않기 위함)
- 버튼 전부 끄기는 그대로 허용 (점 0개 / 정확도 `-`)
